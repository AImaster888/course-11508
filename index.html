1. 為什麼一定要學 GitHub？


先看一個你一定見過的資料夾：


簽稿_v1.docx
簽稿_v2_修改.docx
簽稿_final.docx
簽稿_final_真的final.docx
簽稿_final_科長改過.docx


GitHub 的做法：一份檔案，每次修改自動記錄版本，隨時回到任一版本，雲端備份不怕遺失。


更重要的是——用 AI（Claude、Cursor…）寫東西時，AI 會一直問你「要不要 commit？要不要開 branch？」
聽不懂就只能亂答，最後原本能動的東西被 AI 改壞，再也回不去。

→

→

（毫髮無傷）

3. Git 與 GitHub：誰做什麼


前面兩章一直在說「GitHub」，但真正幫你記版本的，是它底下一個叫 Git 的東西。兩個名字常被混著用，先分清楚：





🔧 Git ＝ 版本控制的引擎

白話：幫你記錄每一次修改的工具本體。


  • 裝在自己電腦裡就能跑，斷網也能用，不一定要有 GitHub。
  • 負責：存版本、比對差異、回到舊版、開分支、合併。





☁️ GitHub ＝ 放 Git 的雲端平台

白話：把這份歷史搬上雲端，再加上給人看、一起改的介面。


  • 建在 Git 之上，多出來的是：網頁介面、Fork、Pull Request、權限管理、Pages 發布。
  • 它存的內容，就是 Git 的版本歷史。







📌 三句話講完關係：

① 沒有 GitHub，Git 照樣跑──它本來就是本機工具。

② 沒有 Git，GitHub 就沒東西可存──GitHub 存的就是 Git 的歷史。

③ 所以第 1 章那顆「後悔藥」是 Git 給的；GitHub 額外給的是雲端備份、別人看得到、能協作。



🔑 今天最該懂的一句：第 9 章你會在 GitHub 網頁上改 index.html、按 Commit changes。那顆按鈕不是「儲存」──是 GitHub 在雲端替你執行了一次 Git commit。你沒裝 Git、沒打過任何指令，但 Git 一直在運作。



哪個字是誰的？






你會看到的字誰的功能白話



RepositoryGit 的概念，GitHub 幫你放雲端專案資料夾＋它的完整歷史


CommitGit存一次檔，留一筆回得去的紀錄


BranchGit開一個平行宇宙試改


MergeGit把平行宇宙的成果合回主線


Push／PullGit 指令，對象是 GitHub本機和雲端互相同步


Fork、Pull Request、Issues、PagesGitHub 平台複製別人的、申請合併審查、追蹤待辦、發布網站







所以下一章的五個核心概念，四個是 Git 的，只有 Fork 是 GitHub 的。



兩條路，同一份歷史

📌 兩條路留下的是同一份歷史。日後想在自己電腦上開發、跑程式或批次修改，用 git clone 把同一個 Repo 抓下來，再用 pull／push 跟 GitHub 同步就好。



✅ 不會 Git 指令沒關係，但要記住：Commit 不是「儲存」，是「留下一個回得去的版本」。

想看證據：打開任何一個 Repo 首頁點 Commits，每一筆改了哪些檔案、哪幾行紅的刪、綠的加，全都在──那就是 Git 的歷史紀錄，GitHub 只是把它畫成好看的網頁給你看。




4. 五個核心概念


不用背指令，但這五個名詞要在腦中有畫面，才能指揮 AI：





① Repository（Repo，倉庫）

白話：你的「專案主資料夾」。


  • 雲端存放一個專案的所有程式、圖片、文件。
  • 唸「瑞剖」；別寫成 repro，那是另一個字。





② Commit（提交，拍照存檔）

白話：對專案現況拍一張「時空快照」。


  • AI 每完成一個小功能就讓它 Commit 一次。
  • 之後寫壞了，隨時「讀檔」回來。頻繁存檔是保命符。





③ Branch（分支，平行宇宙）

白話：複製出一個「平行實驗空間」。


  • 做大改動前先開分支，怎麼改都不影響能動的主程式（main）。





④ Merge／Pull Request（合併）

白話：把平行宇宙的成果「合併」回現實。


  • 分支裡測試沒問題，再合併回 main 正式上線。
  • PR＝多人協作時的「申請合併審查單」。





⑤ Fork（分叉複製）★ 今天的主角

白話：把別人的專案原樣複製一份到你的帳號。


  • 複製後隨你改，完全不影響原作者那份。
  • 原作者更新，你的那份不會自動跟著變（要自己按 Sync fork）。

6. 接上你自己的資料：試算表權限與 ID


Fork 很快，90% 的人卡在這一章。先選路，再動手：






路線 A：Google 試算表連線路線 B：本機 CSV 匯入



設定要開試算表共用權限（下面教）零設定，網頁上點「匯入 CSV」就好


資料去哪試算表變成「知道連結就能看」＝半公開檔案只在你瀏覽器裡解析，不上傳


適合非機密、想要「改試算表→網頁自動更新」公務資料建議走這條，最私密








路線 A 之一：開權限（最多人卡關的一步）


    

  1. 打開你的 Google 試算表 → 右上角藍色「共用」。
    2. 

  2. 找中間偏下的「一般存取權」那區。（⚠️ 不是上面填 email 的框！那是「只給特定人」，前端讀不到。）
    3. 

  3. 預設寫「限制」→ 點它 → 改成「知道連結的任何人」。
    4. 

  4. 右邊角色確認是「檢視者」（千萬不要給編輯者）→ 按完成。
    5. 

  5. ✅ 做對的樣子：該區從「🔒 限制」變成「🌐 知道連結的任何人（檢視者）」，看到地球圖示就對了。
    6. 




路線 A 之二：找出兩個編號


docs.google.com/spreadsheets/d/【SHEET_ID】/edit#gid=【GID】
                               └── 這一長串 ──┘        └ 這串數字 ┘


其實不用自己拆：籤二的工具支援「貼整條網址」，會自動認出 SHEET_ID 和 GID。第一個分頁的 GID 通常是 0。



先自己測一次（分清楚是權限問題還是程式問題）


把這條網址換上你的兩個編號，貼到瀏覽器按 Enter：


https://docs.google.com/spreadsheets/d/你的SHEET_ID/export?format=csv&gid=你的GID


✅ 下載到 .csv 或看到一堆逗號文字＝通了。❌ 出現「你需要存取權」＝權限沒設對，回上面重設。







#讀不到的症狀原因／解法



1要求登入、完全讀不到停在「限制」沒改 ← 最常見


2只有自己看得到只加了某人 email，沒開「任何人」


3下拉根本沒有「任何人」選項機關／公司帳號被管理員鎖 → 改用個人 Gmail 的試算表，或走路線 B


4讀到別的分頁或空白GID 填錯，確認 #gid= 後面那串








⚠️ 資安紅線：「知道連結的任何人可檢視」＝實質半公開。個資、公務機密絕對不能放進走路線 A 的試算表。
另外要知道：純前端網頁「藏不住」資料——瀏覽器讀得到的東西，訪客按 F12 也拿得到。真的要藏資料要走後端（進階，見 Repo 裡的 apps-script-proxy.gs）。




7. 自己從零建 Repo：人工建 vs AI 建


Fork 是複製別人的；自己的東西要上線，就要會建自己的 Repo。兩種都要會：人工建讓你理解每個選項，AI 建是日常姿勢。





👋 人工建（GitHub 網頁）

    

  1. 右上角「＋」→「New repository」。
    2. 

  2. Repository name：英文小寫加連字號（例：my-first-repo）。
    3. 

  3. Description：一句話說明（建議寫）。
    4. 

  4. 選 Public／Private（差別見下一章）。
    5. 

  5. 勾「Add a README file」→ 按「Create repository」。
    6. 

  6. 完成！網址就是 github.com/帳號/repo名稱。
    7. 






🤖 AI 建（指揮 Claude Code）

幫我把這個資料夾建成 GitHub repo，名稱叫 my-first-repo，設為公開，並推上去。


AI 背後執行的其實是一行：


gh repo create my-first-repo --public --source=. --push


前置條件（做一次就好）：裝 Git 與 GitHub CLI，跑 gh auth login --web 完成設備授權（你只在瀏覽器輸入 8 位數驗證碼，密碼不經過 AI）。








8. 管理你的 Repo：公開／私有、更名、刪除



公開 vs 私有






Public 公開Private 私有



誰看得到原始碼所有人（含搜尋引擎）只有你和受邀的人


別人能 Fork 嗎能外人不能（你邀請的協作者依設定仍可）


免費版能開 Pages 嗎能不能（要付費方案）


適合放教材、demo、作品集未完成品、內部資料







⚠️ 一句話記住：「用免費 Pages 部署 ＝ 程式一定公開。」所以機密不能寫死在前端；公開前檢查有無個資、名單、未授權素材——公開後就算刪除，別人可能已經下載了。





👋 人工切換公開／私有

  1. Repo →「Settings」→ 捲到最底「Danger Zone」。
    2. 

  2. 「Change repository visibility」→ 依指示輸入 Repo 名稱確認。





🤖 AI 做法

把 my-first-repo 改成私有。


gh repo edit 帳號/my-first-repo --visibility private --accept-visibility-change-consequences


（新版 gh 要求加最後那個「我知道後果」旗標才肯執行——又是防手滑設計。）







更名





👋 人工做法

  1. Repo →「Settings」→ 最上方「Repository name」→ 改名 → 按「Rename」。





🤖 AI 做法

把 my-first-repo 改名成 course-demo。


gh repo rename course-demo --repo 帳號/my-first-repo






📌 改名最大的雷：一般 GitHub 網址會自動轉到新名字，但 Pages 網址是例外——帳號.github.io/舊名/ 不會自動轉，發出去的連結、QR Code 全部失效。所以：網址發出去之後就別改名；要改就改完重發。



刪除


🛑 刪除是高風險動作，請當作不可復原看待！Pages 網站立刻下線；雖然部分 repo 可在 90 天內向 GitHub 申請還原，但被 Fork 過的有諸多限制、協作權限也不會回來。刪之前先想：改成 Private 是不是就夠了？





👋 人工做法

  1. Repo →「Settings」→ 最底「Danger Zone」→「Delete this repository」。
    2. 

  2. 依指示手動輸入完整名稱（帳號/repo名）才會真的刪——GitHub 防手滑設計。





🤖 AI 做法

幫我刪掉 practice-repo。（AI 應該向你再次確認才執行）


gh repo delete 帳號/practice-repo --yes


第一次會提示權限不足，先補刪除權限（同樣是防手滑）：


gh auth refresh -h github.com -s delete_repo








9. 用 Gemini 改自己的網頁＋課堂練習


Gemini 網頁版不會直接替你存檔到 GitHub；它負責產生 HTML，你負責在 GitHub 貼上、按 Commit changes 存檔。這就是今天要學會的「AI 寫、自己確認、自己發布」。






做什麼實際要按／要貼的內容



① 先告訴 Gemini 要改什麼開 Gemini，貼下面的指令；把 【】 裡改成自己的主題。


② 請它只交出完整網頁回覆請只給我一份完整、可直接貼進 index.html 的 HTML。不要解釋、不要 Markdown 符號、不要分段。網頁主題是「【例如：我的工作小工具】」，內容要有標題、三項服務／成果、聯絡方式；文字用繁體中文，配色簡潔、手機也能閱讀。


③ 到 GitHub 貼上回到自己 Fork 的 Repo → 點 index.html → 右上角鉛筆 ✏️ → 全選原內容、貼上 Gemini 回覆的 HTML。


④ Commit＝存檔頁面最下方的 Commit changes 不用害怕：它就是「存檔」──更精確地說，是 Git 幫你記下一個回得去的版本（第 3 章）。摘要可寫 改成我的個人網頁 → 按 Commit changes。


⑤ 看成果、再修改等約 1 分鐘後重整你的 帳號.github.io/sheet-query-demo/。不喜歡就再請 Gemini 修改，重複「貼上 → Commit → 重整」。

② 用「匯入 CSV」把課堂發的假資料裝進你的網頁（第 6 章路線 B）→
③ 用 Gemini 把首頁改成自己的主題，並在 GitHub Commit 後重整看成果。第 7、8 章留作課後自學。
